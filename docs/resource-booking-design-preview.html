The design question

How can a team member understand availability, reserve one of seven shared resources, and recognize ownership without making conflict rules feel technical? These are independent proposals for the same PRD, not a sequence of revisions. The visual shell, navigation, primary reading order, density, and type treatment differ; demo data and behavior are shared for a fair comparison.

Evidence that informs the proposals

FullCalendar TimeGrid documents day and week time grids. Transfer: aligned time axes in 01 and 02. Adaptation: resource labels and ownership stay visible in event blocks; the HTML recreation is not FullCalendar.

shadcn/ui Sidebar demonstrates composable side navigation and a mobile sheet. Transfer: persistent resource controls in 01. Adaptation: all five use a Filters dialog at narrow widths. No component code was copied.

Carbon data table guidelines describe sortable headers, row actions, and a toolbar for filters. Transfer: 03 makes the booking ledger the main surface. Adaptation: cancellation remains a confirmation dialog, with no bulk action because ownership varies per row.

Radix Dialog documents modal focus management and Escape behavior. Transfer: labelled, focus-contained booking and cancellation dialogs throughout. This file uses native HTML dialog; production should use the PRD’s Radix primitives.

GOV.UK task list pairs concise rows with explicit status. Transfer: readable status and separate actions in 05’s agenda. Adaptation: this is an appointment list, not a multistep task list; that component is not being reused.

Research limits

These are original HTML compositions informed by inspected documentation, not screenshots or copies of shipped applications. Material’s navigation page required JavaScript and an Adobe table link returned 404; neither is used as evidence. No third-party assets, fonts, or source code are embedded. Compatibility with the eventual Next.js component tree has not been verified because that implementation does not exist yet.

PRD contract held across directions

PRD-resource-booking.md, §§4–9: the exact seven resources; 30-minute input; resource multi-select; day/week/list access; All/My bookings; cancelled records; read-only non-owner details; inline conflict IDs, owners and times; confirmation before cancellation; informative toasts.

The preview opens as fictional alex@example.com for immediate comparison. Use Switch identity to inspect the required, non-dismissible email gate over an empty shell. The sample clock is 20 Nov 2026, 07:00 local, so every direction remains reproducible. Fixtures run in memory and reset on reload. Display times use the browser locale; no real booking is made.

Approved direction · 20 November 2026

Interactive coverage and limits

Try switching directions, dates and views; selecting resources; opening events; creating a booking; attempting a conflict; and cancelling an owned booking. Adjacent intervals are allowed; cancelled intervals are freed; rejected attempts do not advance the sample sequence.

This is a design artifact, not the completed MVP. Persistent users/bookings, URL restoration, storage corruption and quota recovery, full 24-hour scrolling, drag selection, dirty-form discard confirmation, and automated WCAG certification remain implementation work. The displayed grid covers 07:00–21:00 with single-slot selection and a keyboard-accessible New booking action. No admin, recurring booking, payment or approval features are introduced.
